## Reasoning

**OWNER — eugene.** `registry/agents.yaml` registers `eugene` with
`owns: [technical-feasibility, architecture, implementation, debugging, testing,
security-engineering, ...]` and `discover_domains` including `frontend` and
`deployment`. `registry/product-routing.yaml` lists `eugene` among
`products.alvira-meos.primary_agents`. The directive's next decision layer is
technical: branch from latest `main`, bring over commit `c698105`'s
sitemap/robots change, run the repository checks, judge the result, and open a
draft PR. That is implementation plus testing inside Eugene's domain. Router
owns `task-classification` and `handoff-enforcement` — flow, not the technical
judgment — and `registry/agents.yaml` restricts Router with
`does-not-become-default-executor`.

**PRIORITY — p1.** Retained from the work order (`priority.level = p1`,
`confidence = 1.0`). The directive describes a live de-indexing defect:
production `sitemap.xml` / `robots.txt` pointing search engines at the dead
`alvira.ctonew.app` host. That is ongoing SEO harm and justifies near-term
attention. Not p0: no outage, security incident, or data loss; the site still
serves; and the fix path is already gated behind owner promotion through the
review card. Not p2/p3: the directive names it the highest-severity de-indexing
defect and TK raised it directly. The live severity ("still serves the dead
domain", "9 URLs verified 200") is reported directive text, not independently
verified here.

**LANE — directive.** The work-order rule reserves `ecosystem` for
operating-layer work and `directive` for product work. This change lives in the
`tk-ap/ALVIRA` product repository (`sitemap.xml`, `robots.txt`), not in the
agent-os-workforce operating layer. Agent OS Workforce captured and routes the
directive, but capturing work does not make it operating-layer work.

**PRODUCT — alvira-meos.** `registry/product-routing.yaml` maps
`products.alvira-meos.repository = tk-ap/ALVIRA`, the repository named in the
directive. Sitemap and robots are core public-site SEO, not the gated `/bridge`
surface, so this is `alvira-meos` rather than `alvira-bridge` (which lists
`tk-ap/ALVIRA` only as `customer_surface_repository` for its `/bridge` route).
`agent-os-workforce` is reserved for operating-layer work and does not apply.

**CAPABILITIES — `[filesystem, git]`.** The directed work creates a task branch
from latest `main`, brings over a two-file change, runs the repo checks, and
opens a draft PR, so `git` is required beyond `filesystem`. Per the work-order
constraint, git runs on either Codex or Claude, so this capability set does not
by itself pin the harness; only a `shell` requirement would force Codex, and
none is declared. `registry/harnesses.yaml` matches: `codex-cli` has
`[filesystem, git, shell]` and `claude-code` has `[filesystem, git]`. Harness
identity is not agent identity (`harness_is_executor_not_agent`), so the owning
agent stays `eugene` whichever harness executes. Note: whether "run the repo
checks" needs a shell is a real open question — see non-decision 3 — and if it
does, the capability set becomes `[filesystem, git, shell]` and execution pins
to Codex. `browser` is deliberately NOT requested: no live-site verification is
in scope for the directed work as written.

**MINIMUM TEAM / AGENT-VS-SKILL.** Eugene alone is the minimum sufficient team.
Per HANDOFF_POLICY.md "Agent vs. Skill Boundary", sitemap/robots editing, git
branch/PR work, and running repo checks are reusable capabilities inside
Eugene's existing implementation/testing domain; they require no materially
isolated context, permissions, independent judgment, or new durable ownership
boundary, so no new persistent agent and no separate SEO owner is warranted.
`agents/marlo/` exists on disk but is not registered in `registry/agents.yaml`
and is therefore not an eligible owner. Whether W Dog (systemic de-indexing
recurrence), Rook (irreversible production-promotion path), or Scout
(post-promotion indexing verification) should compose in is a planning-time
decision for Eugene, not part of this route.

   content.** Owner: Eugene. Missing evidence: the ALVIRA repo state.

   `main`, no merge; production promotion is owner-approved through the review

7. **Dispatch and scheduling.** Whether and when Eugene picks this up, and its

   evidence: current backlog state and capacity.
8. **Downstream review composition.** Whether the directed work needs W Dog,
   Rook, or Scout. Owner: Eugene at planning time. Missing evidence: the rebased
   change and the PR.
9. **Directive closure and the status of #3/#4.** Whether telegram_directives#5
